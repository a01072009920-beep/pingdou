# 移动端 Canvas 布局修复：第一组（步骤 1–3）

用户确认先修复完整显示，再验收并处理连续绘制性能。此次仅修改布局、适应尺寸逻辑、提示结构及对应测试，不修改协议、多人同步或保存行为。

## 问题证据

原手机纵向 flex 布局中，色盘与多行工具栏不收缩，Canvas 容器 min-height 为 0，承受剩余高度压缩。在隔离的 80×80 空画布上，360×619 浏览器视口测得 Canvas 高约 94.6px，适应比例显示 3%。提示位于 Canvas 内部，覆盖画板。

## 改动顺序

1. public/styles.css：手机与 1000px 以内竖屏平板使用画板优先的纵向布局；Canvas 单独分配高度，短屏页面可纵向滚动。窄横屏也保留画布高度。保留原配色、字体、圆角与工具。
2. public/app.mjs：适应算法分别保留左侧32、顶部24、右下12 CSS px；尺寸不变时不重设 Canvas；非适应模式调整尺寸时保持中心对应的棋盘位置；由 requestAnimationFrame 统一安排绘制，不再在 resize 后立即重复画一次。保留原 DPR 上限与绘制细节。
3. public/index.html / public/styles.css：空画布提示移至已有底部信息栏。放豆/擦除只改变提示可见性，不改变画布高度。
4. test/drawing-ui.test.mjs：增加方形、极宽、极高画布的适应边界测试及尺寸重复回调/平移中心保留测试。

隔离服务器、临时数据目录、80×80 画布；未访问生产房间或修改现有作品。

| --- | --- | --- |
| 360×619 | 319×334 | 22% |
| 390×844 | 350×364 | 24% |
| 768×1024 | 727×640 | 47% |
| 1024×768 | 708×398 | 28% |
| 619×360 | 569×320 | 22% |
| 844×390 | 559×350 | 25% |
| 1280×720 | 964×350 | 25% |

以上均无横向溢出，提示位于绘图区之外。桌面浏览器滚动条占用的宽度会影响结果；使用覆盖式滚动条时可多出约15px，因此截图中的比例可略高。短横屏需要纵向滚动到画板区域查看完整画板。

浏览器验证放豆与擦除后的提示隐藏/恢复，Canvas 高度保持640px；控制台无错误或警告。
