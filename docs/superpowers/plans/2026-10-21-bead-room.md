# pingdou Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for inline execution. Steps use checkbox syntax for tracking.

**Goal:** Deliver a local-first collaborative bead board usable alone or across phone and desktop, with erase-before-recolor and 4096-square PNG export.

**Architecture:** One loopback Node.js service owns a durable board. Authenticated WebSockets deliver snapshots and serialized cell changes. A worker generates PNG from an immutable saved snapshot; static browser UI handles gestures and display.

**Tech Stack:** Node.js 24+, ws, native ES modules, HTML/CSS/Canvas, node:test, worker_threads and zlib.

**Spec:** `docs/superpowers/specs/2026-10-21-collaborative-bead-board-design.md`

## Global Constraints

- 64 × 64 logical cells, 24 fixed colors, null means empty; white bead is distinct from empty.
- A click affects one cell; place only into empty; erase any participant's bead before recoloring.
- Save before commit/broadcast; cell revisions reject stale operations. No offline replay.
- Single-user does not wait for others. Same room works on desktop and phone.
- Export exactly 4096 × 4096 PNG; authenticated, immutable snapshot, at most one export worker.
- Default host 127.0.0.1, port 3210, room key in fragment and authentication payload/header.
- Product files live directly in the standalone pingdou project root. Existing unrelated projects remain in their original workspace.

## Review Focus

- Snapshot arriving while a save is pending must not miss the following patch (Task 2 test).
- Old erase after erase/re-place must not remove a new bead (Task 1 test).
- Corrupt file and failed write must preserve prior state (Task 1 tests).
- Touch jitter, drag-out-and-back, pinch and cancellation must never double-place (Task 4 tests).
- Export after an acknowledged placement contains it while later placements cannot alter the captured image (Task 3 tests).

## Task 2: local server and WebSocket protocol

**Files:** src/server.mjs, src/cli.mjs, test/server.test.mjs.

**Interfaces:** `createApp({dataDir,port:0,host:'127.0.0.1',save?})` returns {server,room,start(),close(),address()}; `npm start` serves port3210. Socket client sends {type:'auth',key}, {type:'sync'}, {type:'op',...operation}. Server sends {type:'snapshot',board,online}, {type:'patch',requestId,index,cell,revision}, {type:'rejected',requestId,code,index?,cell?,revision}, {type:'presence',online}, {type:'error',code,message}. Empty erase acknowledges with {type:'unchanged',requestId,index,cell,revision}. No key in snapshots. Server serial queue persists before publishing. GET /api/health returns service status only.

- [x] Write real two-client tests for auth, solo use, conflict, restart and failed-save rollback; observe failure and implement. Test new client snapshot during pending write receives the committed patch.
- [x] Reject oversized/malformed/binary frames and invalid auth without server failure; set heartbeat, bounded rate/pending work, static allowlist and headers. Run full suite.

## Task 3: server-generated 4K PNG

**Files:** src/png-worker.mjs, src/export.mjs, test/export.test.mjs; extend server.mjs.

**Interfaces:** `ExportManager.render(board)` returns Promise<Buffer> and rejects busy; POST /api/export with Authorization: Bearer <key> returns image/png with version filename and no-store. Accept only when authenticated; capture current committed board once at request receipt. Worker writes 4096-square RGB PNG using crc32/deflate; parent event loop remains available.
