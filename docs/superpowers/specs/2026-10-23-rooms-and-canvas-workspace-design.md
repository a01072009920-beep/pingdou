# 多房间与画布优先工作区设计

日期：2026-10-23。状态：实现与验证完成；用户已追加授权发布到 GitHub。

## 用户目标与范围

每位访问者都可以创建独立房间，设置自己的邀请码，或输入朋友的邀请码加入。邀请码与内网穿透网址分开。电脑、手机、平板均以画布为主要操作区域，用户可以收起色盘，并在拼豆时隐藏介绍和辅助界面。

保留现有淡蓝灰背景、圆角、豆形色块和 MARD 色盘；保留离散格子、先擦后换色、多人互相擦除、画布库、清盘备份、行列定位、移动缩放、连续放豆和 4096 × 4096 导出。当前代码没有撤销栈，本轮不把清盘备份描述为撤销，也不扩大到新增撤销功能。

本轮不改连续绘制的发送速率和渲染质量。房间隔离所需的身份验证、广播和保存范围调整属于本轮；其他同步优化仍需性能证据。

## 当前代码确认的边界

- `src/server.mjs` 的 `createApp` 只加载一个 `room`，所有已验证连接共享广播、在线人数和写入队列；导出也固定读取这个房间。
- `src/store.mjs` 只保存 `data/room.json`，其中包含密钥、当前画布和画布库。
- `src/cli.mjs` 与 `scripts/tunnel.mjs` 把同一个房间密钥放在网址片段中。
- `public/app.mjs` 的加入、重连、邀请和导出都使用单个 48 位密钥；现有连接替换时会检查旧 socket，可扩展为房间切换边界。
- `public/index.html` 把工具和色盘放在同一个侧栏；收起侧栏会连常用工具一起隐藏，需先分离。
- `public/styles.css` 的移动端画布采用接近屏宽的固定高度，其余界面依靠页面滚动；桌面侧栏常驻。没有色盘折叠或专注模式。

## 方案选择

采用“同一个服务托管多个独立房间”：复用当前 Node 服务、WebSocket 和本机文件保存，朋友使用同一个网站入口。每个房间独立保存和同步。

每个房间启动单独服务会增加端口和穿透管理负担，不适合用户直接创建房间；增加云端账号、数据库和房间发现服务则会改变本机托管方式。两者不纳入本轮。

邀请码独立于网址，意味着穿透重启、网址改变后，房间和邀请码仍然保留；朋友仍需打开当前有效的网站入口。仅凭邀请码在互联网上自动找到任意电脑，需要额外的公共发现服务，本轮不提供。不同电脑上独立运行的服务拥有各自的房间集合。

## 进入、创建和邀请

1. 不带旧房间凭据的网址进入房间入口，显示“创建房间”和“加入房间”。不公开列出其他人的房间。
2. 创建填写房间名称和邀请码，默认新建 64 × 64 画布，之后可用已有画布功能调整尺寸。房间名为 1–40 个字符。
3. 邀请码为 8–32 个英文字母、数字、短横线或下划线；忽略两端空格，统一大写后匹配。提供“随机生成”按钮，用户仍可自行填写。该服务内重复的邀请码不能创建第二个房间，失败时保留表单输入。
4. 加入只需输入邀请码。服务器验证成功后返回对应房间的随机访问凭据；所有作品读取、操作和导出继续校验访问凭据。
5. “邀请”弹窗分开展示“网站地址”和“邀请码”，支持分别复制及复制完整邀请说明。本轮不自动发消息给朋友。当前为本机地址时沿用明确的跨设备使用提示。
6. 工作区保留“房间”入口，可创建或加入另一个房间。当前存在正在保存的操作时先完成保存，再允许切换，避免未保存笔画被静默丢弃。
7. 不引入账号和房主权限；同一房间内参与者沿用平等协作权限。本轮创建时设置邀请码，不额外引入踢人、删除房间或邀请码轮换功能。

## 存储、旧作品和房间隔离

建议新增 `src/rooms.mjs` 管理房间目录、邀请码查询和每房间运行状态，复用 `src/store.mjs` 的校验与原子保存。

- 原有 `data/room.json` 原位保留，作为“原有房间”载入；启动升级不重写旧作品，也不替换原密钥。旧完整链接仍可进入。
- 新房间使用服务器生成的 UUID，保存在 `data/rooms/<uuid>/room.json`；路径不使用用户输入的房间名称或邀请码。
- 新房间文件包含名称、创建时间、邀请码校验值、随机访问凭据以及现有画布库结构。每个房间单独写入，避免每放一颗豆都保存其他房间。
- 邀请码索引使用 HMAC-SHA-256，服务的随机索引密钥持久化在 `data/room-index-key.json`。不保存明文邀请码。创建和加入成功时，用户刚输入的邀请码保留在当前浏览器会话中，供邀请弹窗复制；旧链接进入的房间尚无邀请码时提供“设置邀请码”。
- 为原有房间设置邀请码时，只新增独立的旧房间元信息文件，不重写旧作品。该操作要求原有房间访问凭据。设置后保持旧链接有效。
- 启动时从有效房间文件重建索引；创建操作串行检查唯一性，文件落盘成功后才将新房间加入内存索引和返回成功。失败不留下可加入的空房间。损坏文件保留并报告，不能静默覆盖。
- 每个 WebSocket 验证后固定绑定一个房间。广播、在线人数、快照、写入队列及画布操作仅作用于该房间。房间 A 保存较慢时，不占用房间 B 的写入队列。
- 保留现有“保存成功后确认和广播”、格子版本检查和画布代际检查。房间切换创建新连接，旧连接的迟到消息、重连定时器和未发送轨迹不能作用于新房间。
- 导出根据凭据选择房间，并捕获该房间的不可变画布快照。可以继续全服务只允许一个导出任务，限制资源使用，但不能复用其他房间的结果。
- 加入与创建接口校验输入长度、请求体大小，并限制连续失败尝试和创建频率。不能将穿透代理转发头直接视为可信用户身份，也不能因共享代理地址使正常用户全部无法加入。
- `data/` 继续整体排除在 Git 之外，日志和测试报告不输出真实邀请码或凭据。

## 前端连接与启动入口

建议新增 `public/rooms.mjs` 负责创建、加入、邀请码表单和会话信息，避免继续把全部房间界面堆入绘制代码。

HTTP 使用创建、加入和旧房间邀请码设置入口；WebSocket 的现有 `auth` 根据凭据选择房间。快照增加房间 ID 和名称。绘制指令中的房间归属以已验证连接为准，客户端不能靠修改一个房间 ID 越权。

前端切换前等待保存完成；切换成功清除旧画布、画布列表、悬停位置和旧下载链接，再加载新快照。加入失败时保留原房间及表单，不把原有可用连接先销毁。暂时断网重连仍恢复同一房间，不重放旧笔画。

本机启动继续支持打开原有作品，同时可通过“房间”创建新房间。穿透脚本改为输出不含房间密钥的网站入口，保留现有启动、锁和退出管理。测试同步更新，实际用户作品不参与验证。

## 画布优先布局

### 常驻操作

紧凑顶栏显示品牌、房间名、连接状态和“房间 / 邀请 / 更多”入口。主要工具条固定保留放豆、橡皮、移动、当前颜色、展开色盘、放大、缩小和适应画板。保存状态与当前行列坐标保持可见。

工具条与色盘内容分离，收起色盘后仍能放豆、擦除、移动和查看当前颜色。画布管理、新建、扩展、清盘和导出通过明确的“画布 / 更多”按钮展开；清盘仍需要原有确认并保存备份。

### 色盘与专注模式

- 电脑默认展开侧栏色盘，用户可一键收起，让画布获得侧栏空间。
- 手机默认收起色盘，通过当前颜色或“色盘”打开底部面板；竖屏平板遵循窄屏布局，横屏空间充足时使用侧栏。底部面板有高度上限并独立滚动，不能覆盖绘制坐标区域。
- 显式提供“专注”切换，隐藏品牌副标题、装饰性介绍、使用说明、冗余版本与统计文本。房间入口、保存状态、主要工具和退出专注按钮仍可访问。
- 帮助说明放入“帮助”入口，任何默认提示都不覆盖画布。
- 折叠和专注偏好只保存到当前设备；不广播给同房间的其他人。存储不可用时使用内存设置，不影响绘制。
- 不在触摸绘制过程中自动切换面板或布局，避免画布位置变化导致错误放豆。按钮有 `aria-expanded` 等状态，收起时隐藏内容不能继续获得键盘焦点。

### 尺寸和缩放

工作区占据当前可视窗口剩余空间，用动态视口高度、安全区和 `minmax(0, 1fr)` 分配画布。正常绘制时不要求先滚过说明和色盘才能操作画布。

极短横屏采用紧凑布局；确实容纳不了工具和画布时允许外围容器滚动，不能把画布压缩为几十像素。色盘关闭时 360 × 619 视口的画布容器目标至少高 350 CSS 像素；短横屏的目标按实际工具区占用核验，不强求不可能的方形画布。

适应状态随容器变化重新计算全景，包含行列标尺和四周留白；手动缩放状态则保留画布中心与缩放值。色盘展开、收起和横竖屏切换都走相同的尺寸更新路径。继续按设备像素比绘制，不以降低清晰度换取性能。

## 验收标准

- 两个新房间使用不同邀请码，作品、画布库、当前画布、在线人数完全隔离；A 的改动不会发送给 B。
- 同房间的手机 / 桌面页面即时协作；空格放豆、先擦后换色、版本冲突和清盘备份规则保持。
- 重启后邀请码和所有房间作品恢复；重复邀请码、无效输入、错误邀请码和保存失败有明确反馈。
- 原有文件在只启动、读取、加入及新建其他房间的测试中保持字节不变；原密钥与旧链接继续有效。
- 错误凭据不能读取、修改或导出其他房间；其他房间保存受阻时，本房间仍可提交和确认。
- 存在未完成保存时不能切换房间；切换完成后旧连接回调和旧导出结果不能改变新房间界面。
- 360 × 619、390 × 844、768 × 1024、1024 × 768、844 × 390、1280 × 720 检查色盘展开 / 收起及专注模式，页面无横向溢出；常用控件触控区域至少 44 CSS 像素。
- 80 × 80 及矩形画布在“适应画板”时包含完整四边和标尺；收起面板不能减小画布区域。放豆、擦除、移动、缩放与坐标定位在布局变化后仍准确。
- 对话框与菜单打开时不触发画布键盘放豆；提示不遮挡工作画布。色盘重新打开保留已选颜色与筛选。
- `npm.cmd test` 和 `npm.cmd run check` 通过，新增浏览器控制台无错误。
- 浏览器视口模拟只能证明布局与事件流程；真实 iOS / Android 的双指手感、软键盘和公网延迟单独列为真机验收，不宣称已验证。
