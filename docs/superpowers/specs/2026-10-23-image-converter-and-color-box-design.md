# 图片转拼豆、房间导入与颜色盒子设计

2026-10-24 用户纠正导入语义：导入应显示颜色/色号参照，实际豆子从零开始。本文“填好新画布”的原方案由 [待拼图纸分层修正](2026-10-24-pattern-guide-design.md) 取代，旧作品仍保留。

日期：2026-10-23。状态：用户已确认并要求实施；2026-10-24 完成本地实现与自动化、浏览器流程验证。真机触控与公网测试仍待用户设备验证。

## 目标与已确定需求

第一版完成“上传图片 → 调整转换 → 核对色号与用色 → 导入当前房间 → 多人修正 → 导出带色号图纸”的完整闭环，并进行整体测试。

用户已明确：

- 图片转换后必须对应具体拼豆色号，图纸中要标注色号。
- 第一版就支持将转换结果放入游戏画布，进行整体测验。
- 增加颜色盒子：有转换图片时自动整理所需颜色；没有图片时，用户能够手动添加想要的颜色。
- 图片所需颜色随画布共享；手动添加的颜色属于各位用户自己，整理个人盒子不影响伙伴。
- 图片转换方法需要改进，不能只搬运参考仓库的基础实现。
- 保留现有视觉风格与画布操作，保护已有作品及房间数据。

以下默认值和技术选择已随整稿确认：导入为当前房间的一张新画布、个人颜色按设备/房间/画布保存、CIEDE2000 配色、三类采样模式、可选颜色上限、分块 PNG 图纸。验证记录见 [整体测试记录](../validation/2026-10-24-image-converter.md)。

## 当前工程边界与方案选择

当前工程是原生 JavaScript 模块与本机 Node.js 服务；参考仓库 sP 是 Vue 工作台。保留现有工程，新增独立转换与盒子模块。借鉴参考仓库的模块职责和交互，自行实现算法与集成，不迁入整套 Vue 应用。参考仓库根目录 LICENSE 查询返回 404，尚无明确源码复用许可，不直接复制其代码、角色样例或模型权重。

当前可选色表为 291 个 MARD 色；隐藏的 24 个旧颜色只用于原作品兼容，不进入转换候选色。MARD 的 code 与现有 HEX 调整是唯一配色依据，不使用参考仓库的 Artkal S 色表，也不补造尚无数据的 331 色。特效组的 HEX 仅为平面屏幕参考，算法不推断材质效果。

现有画布允许 8–256 行列。普通放豆仍严格执行空格可放、先擦后换色。批量导入是一张新空画布的初始化，不逐格覆盖旧作品。

采用“浏览器本地转换 + 房间内批量新建图纸画布”：原始图片不传给服务器，服务器仅接收最终格子色号与经过约束的必要参数。旧画布完整保留，新画布保存成功后全房间切换到它。

考虑过的其他方式：

- 仅输出离线图片：无法满足用户第一版就导入游戏、整体测验的要求。
- 迁入 sP 的整套 Vue 页面：会重复现有画布、色盘和状态系统，并带来编辑规则、房间同步与授权问题。
- 逐格模拟放豆：当前每 50ms 发送一格，80×80 满图仅发送至少约 320 秒；服务端还会逐格持久化。现有 WebSocket 消息上限为 4096 字节，也不能直接承载整图。
- 覆盖当前作品：会冲突于先擦后换色和保留作品的要求。首版统一新增导入画布，不做贴图覆盖、局部合并或替换旧画布。

## 用户流程与页面

“更多”中增加“图片转图纸”入口，进入独立转换工作区。常规绘制仍以画布为主，转换面板关闭后不占据固定大面积。

1. 选择 PNG/JPEG，本机读取并显示原图。首版限 10 MiB、1600 万原始像素；文件头和解码后的尺寸均检查。损坏文件、伪后缀及超限输入给出可理解的提示，保留上一次有效草稿。
2. 默认使用整图，用户可矩形裁剪、恢复整图、查看原图方向。解码遵循图片方向信息，裁剪坐标以解码后的图像为准；由浏览器颜色管理归一化到 sRGB 后再与 MARD HEX 配色。
3. 选择输出画布行列，各为 8–256；默认参考当前画布尺寸，图像按比例完整放入、居中，余下格子留空。首版不提供拉伸或超出边界裁切填满；用户需要铺满时先裁剪到合适比例。
4. 选择转换模式、透明边缘设置、颜色上限及可选的限定色盒。修改参数只生成本地草稿，不修改房间。保留“原图 / 采样结果 / 最终豆色”对照，参数变化时明确草稿仍在更新。
5. 最终预览提供缩放、移动、网格及色号显示，汇总实际尺寸、非空格数、使用颜色数和颜色盒。放大到足够格宽后显示格内色号；导出图纸始终标注非空格色号。
6. 点击“导入房间”前展示：将新增一张画布、同房间伙伴会一起打开、原作品保留。用户可编辑画布名称。存在本人待保存笔画时先完成保存，导入期间暂停本人绘制和重复提交。
7. 导入成功关闭转换工作区并打开新画布；失败保留草稿和参数，可重新提交。转换草稿在本设备关闭窗口后是否保留由实现按内存预算决定，不宣称原图已持久保存；刷新前明确会丢失本地转换草稿。

首版不纳入 AI 主体分割模型、自动语义识别五官、A4 实物尺寸打印、PDF、账号系统和原图云存储。原图已经透明时直接保留；复杂背景可通过裁剪减少，也可以在生成后用现有格子橡皮修正。背景抠图属于后续增强，不作为首版转换可用性的依赖。

## 颜色转换方案

### 共用数据与确定性

浏览器从服务器当前权威 MARD 色表取得 code/HEX，转换时排除 legacy 条目。图案使用稳定色号或 null 表示每格，而非在可移植草稿中只保存数组下标。服务器导入时再次从权威色表按 code 映射。

色表指纹包含有序 code/HEX 及本地覆盖值。客户端与服务器色表不一致时拒绝导入并提示刷新，避免预览、房间与图纸颜色不同。同输入、参数、色表与算法版本必须产生确定性结果；同距以既有色表顺序解决，不重新分配色号。

### 采样与透明度

- 像素画模式：按目标格中心最近邻采样，避免平滑制造额外过渡色。
- 平滑模式：在源区域内进行面积加权，颜色先进入线性光空间，并使用预乘 alpha 计算，避免把编码后的 sRGB 直接平均，或把极低透明度当作完整可见面积。
- 卡通模式：区域主色结合局部高对比边界权重，减少前景与背景混成新颜色；边界权重与范围由实现通过固定样图校准，并提供有界的轮廓保护强度。不能把粗 RGB 分箱称为真实轮廓识别，也不保证任何尺寸下都保留所有细线。

区域可见覆盖率按实际 alpha 面积计算。完全透明或被居中留白覆盖的格子为 null；区域模式的默认放豆覆盖率门槛为 50%，可在 10%–90% 调整并即时预览。像素画模式也应用明确的 alpha 门槛，避免几乎透明的像素被变成实心豆。普通不透明白色内容照常匹配白豆，不能自动删除全部近白色像素。

半透明前景在提取颜色后与用户指定底色合成；默认白色，界面展示该默认值。底色仅用于非空前景的颜色计算，不能把完全透明区域填满。原始 RGBA 保持不变。

### 配色与颜色数量

候选色预计算 CIELAB，采用自行实现并以公开测试数据验证的 CIEDE2000 色差匹配；保留 CIE76 作为验证基准，不把更换公式视为所有图片效果必然更好的证明。

默认不设硬性颜色数量上限。提供 16 / 24 / 32 / 自定义上限；用户可锁定指定颜色。上限小于锁定颜色数量时提示调整，不静默取消锁定。

减少颜色时综合使用频率、颜色合并误差与边界权重选择 MARD 子集，再让全部非空格重新匹配最终子集；不能只保留出现最多的颜色并丢弃其余格子。实现可选择确定性的贪心或加权聚类，但必须只输出真实候选色，不创建虚构色号、不产生漏格，并与无限色结果对照。

“仅使用盒子里的颜色”是显式选项，默认关闭。开启时使用本地草稿最终盒子的候选集合，包括个人添加色；空集合拒绝生成。为了避免自动生成清单反过来不断缩小候选集，转换开始时固定候选色快照，输出清单不自动重定义本次输入。手动收藏颜色不会默认限制转换。

抖动首版默认关闭且不提供额外算法入口，避免增加零散色点和范围；后续若需要照片专用抖动，另做同尺寸对比。

### 性能与任务管理

采样和配色在 Worker 中运行。预计算色表数据、缓存重复采样色；采样缓存与配色缓存分开，改变色数上限或候选色不重新解码原图。

每次转换携带任务代号与参数快照。新任务取消旧任务或令其结果失效；旧任务不能覆盖最后设置的预览。显示当前阶段与进度，支持取消。取消或失败不修改房间，不清除最后一次有效预览。

浏览器本地的预览、导入载荷和直接导出均从同一份已完成的最终网格派生，不能分别重新计算而产生不一致。转换参数尚未应用、任务运行或结果过期时禁止导入。

## 颜色盒子

### 两类归属

1. 图片所需颜色：从最终非空格准确计数，保存为导入画布的共享参考清单，包含色号与原始需要颗数。随该画布保存、重开和房间快照同步。服务器从导入格子重新计算，不信任客户端传来的颗数。
2. 个人手动颜色：本设备浏览器保存，按房间 ID + 画布 ID 区分，不发送给其他参与者。没有登录身份，因此“个人”不等于跨手机、电脑自动同步；穿透网址更换、浏览器换用或清除存储可能影响本地收藏。存储不可用时当前会话仍能选色，给出简短说明。

转换尚未导入时，手动颜色属于本设备转换草稿；进入转换器时复制当前画布的个人颜色作为起点，草稿里增删不会反过来修改当前画布的个人盒子。成功导入后其色号并入新画布的个人盒子。既有画布的个人盒子不被替换。

### 色卡与排序

盒子去重，按 A、B、C、D、E、F、G、H、M、P、T、R、Y、Q、ZG 排列，同组数字升序；另标 1…N 盒内序号。相同 code 同时来自图片和个人添加时只显示一张卡，保留来源信息。

色卡显示色块、MARD 色号；图片用色显示“原始图纸需 N 颗”。当前画布实际用量在详情/统计中另外显示，手工修改不能把原始参考用量悄悄改写。点色卡复用现有选色状态，不创建第二套画笔颜色。

个人添加支持搜索完整色盘、多选、去重和移除。移除个人快捷色只影响个人列表，不能擦除格子、修改共享参考清单或重算配色。共享图片用色不能通过个人整理直接删除；重新生成并导入新的图纸才产生新的参考清单。

未上传图片的新画布没有共享图片用色，显示“添加我的颜色”入口。保留完整色盘入口，普通绘制不会因为盒子未添加颜色而失效。

手机和平板使用可收起的紧凑盒子；常用工具、当前颜色和展开按钮始终可达。颜色数量较多时在盒子内部滚动，不持续挤占画布高度。展开/收起是设备本地偏好，不改变伙伴布局。

### 画布生命周期

- 切换画布：加载该画布的共享参考清单和本设备对应的个人颜色。
- 新建空画布：无图片参考清单，个人盒子为空，旧画布及其盒子保留。
- 扩展画布：保留原坐标、参考清单与个人盒子；新增空格不增加参考用量。
- 清盘：沿用已有整张备份。备份保留图片参考信息；当前清空画布也保留参考颜色以便重新拼，当前实际用量为零。不能把原图参考颗数显示成已放颗数。
- 重新打开或服务重启：共享参考信息从房间文件恢复；个人颜色从本地恢复。

## 批量导入与房间一致性

新增同源、需当前房间访问凭据的 HTTP 导入入口，不扩大所有普通 WebSocket 消息的 4096 字节限制。请求体上限建议为 1 MiB，并限制读取超时与同房间同时等待的导入数量；输入为稳定 requestId、名称、宽高、按行优先排列的 code/null 数组、色表指纹和有界转换参数。服务器不接收原始图片、客户端自定义 HEX 或任意文件路径。

服务器验证 8–256 行列、格数完全匹配、名称长度、code 存在、参数类型/长度和色表指纹。每个数组位置恰好表示一个格子，不能遗漏某些转换格子后仍报成功。未知色号和非法数据整单拒绝。全透明图片可以生成全空草稿，但导入前明确提示“没有可见豆子”；允许用户按普通空画布继续导入，清单为零色零颗。

验证后进入对应房间的现有 entry.queue。导入点击时捕获 activeId + canvasEpoch；如果进入队列时画布上下文已被别人切换、扩展或清盘，拒绝并保留草稿，提示重新核对。普通单格编辑造成 revision 增长不必拒绝新增画布：入队执行时保存旧画布的最新有效版本，再添加新画布，避免丢掉伙伴刚保存的豆。

导入构造权威 board 与共享参考清单，一次原子保存完整新房间状态，成功后更新内存并广播房间快照。新画布推进 canvasEpoch；旧画布的迟到绘制仍走现有过期检测。另一个房间不受到排队、作品或广播影响。

requestId 与载荷摘要记录在导入画布元数据中，用于重试去重。同房间相同 requestId、相同摘要返回原导入结果；不同载荷使用同一 requestId 时拒绝。重试不能重复新增作品，不能为了返回旧导入结果把伙伴当前正在看的画布再次强制切回。客户端收到较早的 HTTP 响应也不能覆盖更新的房间快照，应以当前 WebSocket 状态为准，必要时重新同步。

HTTP 超时、断线或广播失败不代表保存失败；客户端保留稳定请求编号以查询/重试，最终依据服务器确认结果显示状态。用户若更换房间，旧转换结果只能继续作为本地草稿，不能自动提交到新房间。

## 数据与兼容性

画布增加可选导入元信息：版本、请求编号与摘要、算法/色表版本、转换设置、共享参考用色。存储校验必须理解这些字段，并限制深度、字符串与数组长度。无元信息的旧画布继续有效；启动不重写旧文件、不替换房间密钥或邀请码索引。

不新增原图持久化；重新裁剪、重新转换仍需要原图。导入后修改格子不会修改原始参考用色；导出当前图纸的材料统计始终按当前格子计算。

现有通用多人撤销栈并未实现。本轮不把清盘备份或保留旧画布称为撤销，也不迁入 sP 的直接覆盖式单人撤销栈。共享画布继续遵守原有放豆与擦除规则。

验证和人工演示全部使用临时数据目录，不写入、清盘或公开真实 data/、作品、房间密钥。文档和公开截图只使用合成样图与临时房间。

## 图纸与导出

原有 4096 × 4096 成品 PNG 导出保留。另增加“带色号图纸”：方格内填最终豆色，每个非空格标完整 MARD 色号，文字按底色选择足够对比的黑/白；空格使用清晰的留空标记或浅背景，不当成白豆统计。

图纸包含作品名、色表/版本、画布行列、行列编号、格线、颜色图例、各色当前颗数与总颗数。颜色排列沿用既有 MARD 顺序，图例只包括实际非空格使用色，不把未使用的个人收藏色列为材料。

大画布不能靠把全部文字缩进 4K 图来宣称可读。首版提供固定每格 32px 的分块 PNG（每块最多 64×64 格），标注全局行列范围；边界格各出现一次，不漏格、不重复材料总数。整图总览不承担原始尺寸下阅读每个色号的要求。多个文件下载受浏览器限制时允许逐块手动下载，不自动循环弹出大量下载。

图纸渲染使用已完成的本地草稿或已同步的当前画布不可变快照，采用浏览器 Canvas/OffscreenCanvas 能力；支持不足时分段绘制，避免在房间绘制主循环里长期阻塞。实际导出最大尺寸与手机内存通过测试确定。

## 验证与验收

### 转换质量

同一原图、裁剪、目标行列和 MARD 色表下，对比参考式 CIE76/普通面积采样与新方案；不同时改变尺寸后把改善归因于算法。使用有权使用的固定样图：已有像素画、黑线卡通、肤色照片、渐变、透明 PNG、白色主体、半透明抗锯齿边缘。

记录实际颜色数、总颗数、零散色点、关键轮廓/细节及人工修正量；平均色差仅作辅助。极低网格分辨率可能无法表达原图细节，不宣称自动修复不存在的格子信息。精确色表颜色应按确定性同距规则映射；CIEDE2000 通过公开参考数据。

验证各种 alpha、纯白与空格区别、纵横长图居中、8×8/80×80/128×128/256×256、颜色上限与锁定颜色、个人限定色盒、取消/快速换参数/坏文件保留有效结果。

### 一致性与数据保护

- 预览每格 code、颜色盒原图用量、导入格子与草稿图纸一致；总用量等于非空格数量。
- 当前画布编辑后，原图参考用量不变，当前图纸统计正确。
- 批量导入只做一次持久保存，保存失败零副作用；重试、服务重启和同编号不同载荷正确处理。
- A 房间导入不影响 B 房间；慢保存不阻塞另一房间的操作队列；未授权或跨源请求拒绝。
- 导入遇到画布生命周期变化可拒绝并保留草稿；普通伙伴笔画不丢失；旧 HTTP/WS 结果不回退新状态。
- 旧画布、legacy 色、房间索引密钥、画布备份保持有效；扩展/清盘/重开后元信息符合本稿规则。
- 两个浏览器看到相同共享清单，但个人加色和移除互不影响；切房间/画布不串盒子。
- 图纸分块边界、全局坐标、长色号、黑白文字、材料统计和导出期间继续编辑均正确。

### 运行与设备

执行 npm.cmd test 与 npm.cmd run check，并做浏览器完整闭环验证。80×80、128×128、256×256 分别记录转换各阶段耗时、取消响应和导入耗时；手机转换不能长时间冻结界面，不能通过漏格或降低图纸清晰度换帧率。

桌面、手机和平板布局与触摸流程分别验收；浏览器窄屏模拟与真实设备报告分开。当前没有实际设备测量基线，不承诺未经测量的秒数。真实手机/平板与 Cloudflare Tunnel 的访问延迟需要实际测量，不能把本地浏览器结果视为公网设备结论。
