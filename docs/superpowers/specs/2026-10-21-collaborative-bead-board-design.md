# 拼豆板：单人及跨设备协作设计

日期：2026-10-21

状态：用户已于 2026-10-21 确认设计并要求制作；第一版本机实现已交付，公网连通与手机真机验收待完成。

## 1. 目标与已确认的规则

一个人可以直接开始拼豆，也可以邀请另一人通过浏览器共同完成同一张作品。支持电脑、手机和平板混合加入同一房间。网页服务运行在用户的 Windows 电脑上，通过内网穿透提供远程访问。作品数据保存在这台电脑上。

用户已经确认：

- 以一个格子为一次操作的单位，选择颜色后点击空格上色。
- 已有颜色的格子不能直接更换颜色，必须先使用橡皮擦空，再重新上色。
- 双方可以擦除对方放置的豆；不区分豆的所有者权限。
- 双方可以同时读写，并看到相同的共享拼豆板。
- 手机与电脑可以共同操作，采用相同的拼豆规则和共享状态。
- 没有其他参与者时可以独立拼豆、保存和导出，无需等待另一人上线。
- 导出图片需要达到 4K 级别。

第一版采用的具体默认值：64 × 64 格、24 色固定调色板、单张共享板、邀请链接加入、自动保存及 4096 × 4096 像素的正方形 PNG 导出。4K 指导出图片的分辨率；逻辑格子数量仍为 64 × 64。目标使用人数为一人或两人；不加入账号系统或强制人数上限。持有完整邀请链接的人拥有相同的放豆、擦除和导出权限。

单人和协作使用同一个房间，不需要切换模式。页面有一位参与者时即可完整操作；其他人随后加入会看到已经完成的作品，最后一位协作者离开后仍可继续拼豆。单人使用仍需电脑上的本机服务运行，不包含脱离服务器的离线模式。

## 2. 交互与界面

界面是一张拼豆工作台。中央为规则排列的格子与定位点，有豆的格子呈现该颜色的圆形豆及中心孔；左侧为调色板、当前颜色和“放豆 / 橡皮”工具；顶部显示连接状态、在线人数、“复制邀请链接”和“导出 4K PNG”。手机上画板优先占用可用空间，工具与调色板在底部紧凑排列，兼容横屏、竖屏及手机安全区，不遮挡当前可操作区域。

视觉采用淡蓝灰工作台、浅色拼豆底板和清晰的深蓝文字，彩色豆作为主要视觉内容。基础色值：工作台 #E9EFF5、底板 #FAFCFF、边界 #CCD9E5、文字 #24394B、主操作 #3668C9；字体使用本机中文无衬线字体。避免依赖在线字体和远程图像，以便本机服务独立运行。

操作规则：

| 当前格子 | 工具 | 结果 |
| --- | --- | --- |
| 空格 | 放豆 | 放入所选颜色的一颗豆 |
| 有豆 | 放豆 | 保持原样，提示“先擦除这颗豆，再放入新颜色” |
| 有豆 | 橡皮 | 擦除，恢复为空格 |
| 空格 | 橡皮 | 保持为空格，不产生有效修改 |

每次完整点击最多操作一个格子。按住拖动不会连续放豆或连续擦豆；用于移动板面的手势不触发放豆。缩放、滚动与格子坐标换算保持一致。放豆与擦豆必须收到服务器确认后才显示为完成；等待中的格子显示轻量提示，并暂时阻止在同一格重复提交。

手机上单指轻点放豆或擦豆，单指拖动平移板面，双指缩放并平移。只有同一次手势始终为单指、整个轨迹相对按下点的最大偏移未超过 8 CSS 像素、且抬起时仍落在同一逻辑格子时，才提交单格操作。出现第二个触点、明显移动或 pointercancel 时取消本次落豆，直到所有手指离开才重置；双指手势结束后剩下的单指也不能误触发落豆。滚动工具区不操作板面。只使用一套指针事件提交操作，避免触控后附带的鼠标点击重复放豆。

桌面保留鼠标操作和显式平移方式；所有设备提供“放大 / 缩小 / 适应画板”按钮，不要求必须使用双指手势或鼠标滚轮。工具点击区域至少为 44 × 44 CSS 像素，密集格子可通过放大后精确选择。界面至少适配 360 CSS 像素宽度的手机视口。

空格与白色豆必须在数据与界面上明确区分。颜色在数据中使用调色板编号，空格使用 null。

键盘可切换工具、移动当前格子和提交操作；工具及调色板有名称、选中状态和可见焦点。连接与拒绝原因使用中文提示。

## 3. 架构选择

采用 Node.js 本机服务、原生 HTML/CSS/JavaScript 前端以及 WebSocket 双向同步。页面与 WebSocket 共用一个本地端口，方便穿透。除 WebSocket 服务库外，尽量使用 Node.js 内建功能，降低安装与启动成本。

不采用浏览器之间直接对等同步：中心服务器可以统一执行“先擦后放”的规则，处理争抢同一格的操作，并保存作品。不采用云数据库作为权威数据源：用户明确要求由自己的电脑承担服务器。

职责分为：

1. 前端工作台：选色、选择工具、单格点击、显示状态、导出与邀请。
2. 拼豆规则模块：校验坐标、颜色、格子版本和放豆 / 擦除条件。
3. 同步服务：认证连接、发送快照、按顺序处理操作、广播修改和在线人数。
4. 本机存储：加载作品、校验文件、原子写入完整状态。
5. 图片导出：在用户电脑上从已保存的板面快照生成 4K PNG，通过认证的 HTTP 接口交付给请求设备。

## 4. 并发与数据流

服务器保存唯一权威状态：板面尺寸、固定调色板、4096 个格子的颜色与版本、全局版本，以及房间访问密钥。格子版本从 0 开始；每次有效修改增加该格子的版本和全局版本。

加入流程：电脑或手机浏览器读取同一个邀请链接中的房间密钥 → 连接同源 WebSocket → 提交密钥认证 → 服务器发送完整板面快照与版本 → 页面立即允许操作，不等待第二位参与者。认证前不得发送板面数据。

每次放豆或擦除请求携带请求标识、操作类型、格子索引、用户看到的该格子版本；放豆请求另外携带颜色编号。服务器将所有修改放入同一串行队列：

1. 校验消息大小、字段、坐标、颜色和当前连接的认证状态。
2. 校验该格子版本仍然一致，防止旧页面或延迟请求修改已经变化的格子。
3. 放豆要求当前格子为空；擦除允许双方操作，空格擦除不产生修改。
4. 生成候选新状态并持久化成功后，才替换内存状态并向所有参与者广播。

两个请求争抢同一个空格时，第一个被服务器接受并保存的请求成功。后一个因格子版本变化或已被占用而被拒绝，同时收到该格子最新状态，并提示“格子已变化，请重新点击”。客户端不自动重试被拒绝的操作。不同格子的有效请求不会因为其他格子变化而被拒绝。

格子版本必须在“擦空后又重新放豆”的情况下继续递增，不能重置。延迟到达的旧擦除请求因此不能误擦后来新放的豆。

每次有效广播携带修改后的格子状态和全局版本。前端忽略重复的旧版本，发现版本缺口时停止提交并重新请求完整快照；快照与后续广播的发送顺序必须一致。替换连接后，旧连接收到的消息不得修改当前界面状态。

## 5. 断线与保存

连接状态区分“连接中”“已连接”“正在重连”和“无法连接”。未收到初始快照或连接中断时禁止提交修改；断线期间的点击不排队，不在重连后自动重放。重连后以服务器完整快照恢复板面。

服务端心跳清理失效连接；客户端采用逐步延长间隔的自动重连。在线人数统计通过认证且仍然存活的连接数，多个浏览器标签页会分别计数。

作品与访问密钥保存到服务目录下的本机数据文件，数据目录不提交版本管理，也不通过静态文件接口提供。首次启动生成空板和不可猜测的随机密钥；后续启动复用已保存的板面和密钥。

每次有效操作先写同目录临时文件，再原子替换正式文件。写入成功后才向客户端确认和广播；写入失败则保持上一个已保存的状态，向操作发起方提示失败。不得用未保存状态向其他人展示成功。启动时若已有数据文件损坏，应明确报错并保留原文件，不能静默覆盖为空白板。

这一保存策略优先确保已确认修改能在正常重启后恢复；不承诺在磁盘故障或突然断电后绝对不丢失数据。

## 6. 邀请与内网穿透

本机服务默认只监听回环地址；穿透程序映射这个本地端口。公网入口使用 HTTPS/WSS，本机回环地址使用 HTTP/WS。单条客户端消息限制为 4 KiB，并限制单连接提交频率。邀请密钥存放在链接 fragment 中，网页读取后通过 WebSocket 认证消息提交，避免作为 URL 查询参数出现在常规访问日志中。图片导出请求通过 Authorization 请求头传递同一密钥，不能将密钥拼进下载 URL。前端只把状态当作文本处理，不插入为 HTML。

界面“复制邀请链接”使用当前访问页面的来源地址。因此通过公网地址打开后，复制得到公网邀请链接；本地地址打开时，应提示这个地址只适用于本机，并引导先打开穿透程序给出的公网地址。提供操作说明，避免把 localhost 链接直接发给朋友。

穿透首选 Cloudflare Quick Tunnel 进行两人试用：临时公网地址会在重新建立隧道后改变。长期使用可替换为固定地址隧道，应用本身仍使用相同的本地端口。用户电脑、服务和穿透程序需同时保持运行。

手机无需安装专用应用，通过浏览器打开公网邀请链接即可加入，可以使用与电脑不同的网络。手机中的 localhost 指向手机本身，不能作为电脑服务地址；跨设备使用统一的公网链接。手机切到后台后连接可能中断，回到页面时按重连流程重新获取快照，再恢复操作。

随产品交付本机启动脚本、依赖安装说明、双窗口试用步骤与 Windows 穿透操作说明。应用提供可配置端口；不把第三方穿透凭据写入项目文件。实际公网连通性应在可用网络中验证，未完成时应明确标注。

## 7. 4K 导出与范围

默认导出 4096 × 4096 像素的正方形 PNG。每个逻辑格子精确对应 64 × 64 个输出像素，白色底、按格子输出平整色块，边缘不模糊，不包含工具栏和连接信息，也不裁切或拉伸成 16:9。空格输出为白色，已放白色豆在导出图中同样为白色；作品编辑状态中的二者仍然严格区分。

由用户电脑上的服务生成图片，手机或电脑浏览器下载同一规格的文件，避免要求手机浏览器创建或绘制 4K 大画布。导出开始时捕获服务端最新已保存的板面及全局版本，整张图片始终使用该份不可变快照；生成期间继续拼豆不会混入这次导出。界面在本端尚有未确认操作时暂缓导出，并提示等待同步。

像素生成与 PNG 编码均不能长时间同步占用服务器主循环，通过分块让出执行、流式处理或后台任务避免阻塞实时协作；每个服务同时只处理一个导出任务。其他导出请求收到“正在生成图片，请稍后重试”的可重试提示，不排无限队列。导出不修改共享作品，不新增格子版本。下载响应禁止公共缓存，文件名包括作品版本和导出尺寸；未认证请求不能获取作品图。下载中断或编码失败不影响房间和已保存作品。

电脑提供下载，手机通过浏览器支持的下载或系统保存入口保存文件，并提供必要的中文指引；不承诺网页可以直接写入手机相册。生成失败时保留作品并允许重新导出。验收必须读取实际 PNG 的尺寸和内容，不能仅检查按钮文案或文件名。

第一版不加入自由笔刷、按住拖涂、直接覆盖颜色、填充工具、批量清空、撤销重做、多图层、参考图片导入、聊天和账号系统。先保证单格拼豆、双方同步、互相擦除和本机保存稳定。

## 8. 验收

- 只有一个浏览器连接时，无需等待第二人，可以放豆、擦豆、自动保存和导出；第二人加入后看到已有作品，离开后第一人仍能继续操作。
- 电脑与电脑、电脑与手机、手机与手机使用同一邀请链接，看到相同板面；任一方放豆或擦豆后另一方同步更新。手机与手机协作时，本机电脑仍作为服务器运行。
- 有豆格子收到另一个颜色的放豆请求时，前端与服务器均不能直接覆盖；同色重复放置也不能作为修改绕过规则。
- A 放豆，B 可以擦除；擦除后任一方都可以在该格重新放豆。
- 两方同时在同一空格放豆，只有一个请求成功；两方在不同格放豆都成功。
- 延迟的旧放豆或旧擦除请求被格子版本拒绝；连续擦除不会制造额外修改。
- 白色豆能够区别于空格；在 360 CSS 像素宽手机视口、横屏与竖屏下可以选色、切换工具和精确操作。板面缩放、平移、工具区滚动、双指结束与触控取消不会误触发放豆或擦豆。
- 服务重启后恢复已确认的作品；写入失败不广播成功；损坏文件不会被自动清空覆盖。
- 断线时禁止操作，重连恢复最新快照，旧点击不会重放。
- 无效密钥拿不到板面；异常消息和越界坐标不会改变数据或导致服务退出。
- 从电脑和手机导出的文件均为可正常解码的 4096 × 4096 PNG，与所捕获版本的格子颜色一致，边缘清晰，不含工具栏、选中框和网格线。刚放豆后立即请求导出会等待本端确认，文件中包含该豆；导出开始后的新修改不混入。导出期间继续拼豆仍能同步，生成失败可重试；未认证导出被拒绝。
- 手机退到后台再返回时恢复最新已保存板面，不重放旧点击。交付时明确区分真实移动设备测试、浏览器触控模拟测试与未验证项。
- 本机启动和穿透说明可按步骤执行；说明覆盖手机跨网络加入与保存 4K 图片。

## 9. 技术参考

- [MDN：Canvas 最大尺寸随浏览器与环境变化](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/canvas#maximum_canvas_size)。因此把 4K 导出放在本机服务端完成，手机仅承担交互和文件下载。
