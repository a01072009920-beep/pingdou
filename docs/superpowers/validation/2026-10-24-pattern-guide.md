# 待拼图纸修正验证

用户纠正了上一版的导入行为：图纸应作为画布上的颜色/色号参照，由用户亲自放豆。本记录取代上一轮“导入即成品”的验收结论。

- 自动化：`npm.cmd test` 143/143 通过；`npm.cmd run check` 29 个模块通过；diff 检查通过。
- 新导入的实际 cells 全空，目标 reference 保存逐格色号。目标格可自由放豆、伙伴擦除，目标内容始终不变。
- 新增先红后绿测试：图纸渲染/空格可放、擦后露出色号、完整目标导出快照；服务端空导入、实际放擦/重连/重启、严格持久化数据校验、旧 schema 1 作品保留、4K 仅导出实际作品。
- 独立只读复查未发现重要问题，专项 33 项测试通过。扩展后的目标位置按原图纸宽度映射，新增区域留白；清盘保留目标和备份；普通新画布没有目标层。

## 浏览器实测

使用临时目录与自制花朵样图，没有修改用户 data/：

1. 上传 PNG → 卡通 / 16×16 / 3 色 → 导入为待拼图纸。主画布显示 F2/A5/R18 平面色块和色号，已放 0 颗；颜色盒列出图纸需 72 颗，已放均为 0。
2. 选择 A5，点击第 8 行第 8 列，已放变为 1；刷新页面仍保留图纸和这一颗豆子。不是自动填好作品。
3. 在只拼一颗时导出并实际下载色号 PNG，仍有完整 72 个目标格和原材料用量。人工查看文件确认色号、行列和完整图案。
4. 用橡皮擦除这一颗后，已放回到 0；原位置重新显示目标 A5，目标总量仍为 72。
5. 390×844 手机浏览器尺寸没有横向页面溢出，画布操作区域约 456px 高；色号和已放 0 的状态可见。真实手机触控、文件保存和穿透延迟没有在本轮进行硬件实测。
